# 후속 검증 과제

인지적 워크스루에서 발견된 문제 중 아직 실제 사용자 조작으로 확인하지 못한 항목만 관리한다. 이미 구현된 변경은 종합 문서에 기록하고 이 목록에서 제거한다.

## 우선 검증

- 실제 Figma에서 `Open popup → Popup 편집 → Close popup` 흐름이 끊기지 않는지 확인한다.
- Popup이 없는 상태에서 `Open popup` 선택이 새 구조를 만든다는 사실을 클릭 전에 예측할 수 있는지 확인한다.
- 사용자가 `Default · prototype`과 조건 `Case · flow` 중 실제 Figma Prototype에서 실행되는 범위를 구분하는지 확인한다.
- 초보와 중수가 `States`를 Popup 목록이 아니라 일반 오류·로딩 상태로 이해하는지 실제 조작에서 확인한다.
- 원본 Screen 삭제 확인에 표시되는 파생 State와 incoming 연결 수가 실제 삭제 범위와 일치하는지 확인한다.
- Section·요소·Case 삭제 전 영향 인지 또는 삭제 직후 복구가 필요한지 관찰한다.

## 반복 작업 UX

- 화면이 많을 때 네 개 단위 줄바꿈과 화면 간격이 전체 Flow 탐색에 적절한지 실제 캔버스에서 측정한다.
- Screen details 접근과 blur 저장에 완료 피드백이 필요한지 관찰한다.
- Popup 편집 뒤 Back이 사용자가 기대하는 원본 Screen과 source Button으로 복귀하는지 확인한다.
- Flow의 선택 화면과 전체 프로젝트 목록이 같은 연결을 반복해서 보여 주는지 확인하고, 반복된다면 필터 하나로 합친다.

## 보류

- Snackbar는 Figma Plugin API로 하단 위치를 보장할 수 있거나 실제 요구가 반복될 때만 다시 검토한다.
- Figma Variable, Variant, 범용 조건식과 `actions[]` 워크플로 엔진은 현재 범위에 추가하지 않는다.
