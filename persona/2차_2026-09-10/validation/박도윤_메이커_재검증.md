# 박도윤 — Product Maker 2차 독립 재검증

## 참가자와 방법

- 프론트엔드 개발자 출신 B2B SaaS Product Maker 8년 차
- Figma Auto Layout과 기본 Prototype에 익숙한 상급자
- 리뷰 전 30분 안에 주문 흐름과 예외 상태를 만드는 상황
- 기존 연구를 읽지 않고 실제 UI, plugin, shared 구현만 확인함

## 1차 과업 — 4화면 주문 흐름

`상품 목록 → 상품 상세 → 주문 확인 → 주문 완료`를 만들었다.

- 화면 생성과 자동 배치, 기본 블록, 실제 Navigate reaction, connector, Flow와 Spec의 기본 루프는 구현상 성립했다.
- 한 행 네 개 제한은 끝없는 가로 배치를 막지만 모바일 프레임 사이 320px은 여전히 넓었다.
- Screen details는 기본 작업을 방해하지 않지만 Section 편집 중에는 숨고, 화면 속성과 요소 속성 사이 이동이 길었다.
- Notes는 데이터 처리와 후속 효과를 남기는 데 유용하나 요소 description을 공유해 버튼 설명과 action 설명이 분리되지 않는다.
- 조건별 결과나 여러 행동은 Notes로 구조화할 수 없었다.

선형 흐름은 성공했지만 실제 주문의 조건과 예외까지 포함하면 **부분 성공**이다.

## 2차 과업 — 결제 상태, 삭제 복구, Popup/Snackbar

주문 확인 화면을 복제해 `결제 처리 중`, `결제 오류`를 만들고 목적 화면 삭제와 재연결을 수행했다.

- 구조 복제는 성공했고 상태 화면 제작 비용을 낮췄다.
- 모든 cloned reaction과 Feature가 빠지지만 안내가 없어 “복제 성공처럼 보이는 조용한 prototype 누락”이 됐다.
- 같은 트리거에서 성공과 실패로 분기할 수 없어 별도 가짜 버튼 또는 Notes가 필요했다.
- Delete는 데이터와 Figma reaction을 안전하게 정리했고 삭제 후 새 Destination을 설정할 수 있었다.
- 연결 자체를 지우므로 깨진 링크는 남지 않지만 어떤 연결이 사라졌는지 기억해야 했다.

Popup과 Snackbar는 별도 전체 화면 상태 또는 Describe로만 우회할 수 있었다. `Open overlay`, `Close overlay`, delay, dismiss, timeout이 없어 실제 사용자 경험을 검증할 수 없었다.

## 최종 판정과 우선순위

전체 판정은 **부분 성공**이다.

1. Duplicate와 Delete의 연결 영향을 조작 전에 표시해야 한다.
2. 삭제 시 broken link를 복구 가능하게 남기거나 즉시 새 목적지를 고르는 경로가 필요하다.
3. 완전한 상태 엔진보다 `Open overlay`, `Close overlay`, `Show transient message`의 작은 실행 행동 집합이 우선이다.
4. Screen details 접근성과 Flow 중복을 개선해야 한다.
