# 김서윤 — Product Designer 2차 독립 재검증

## 참가자와 방법

- B2C 커머스 Product Designer 6년 차
- Figma 컴포넌트, Auto Layout, Prototype을 매일 사용하는 상급자
- 리뷰 전 20분 안에 구매 흐름과 예외 상태를 공유하는 상황
- 기존 연구 문서를 보지 않고 현재 구현만 확인한 인지적 워크스루

## 1차 과업 — 4화면 구매 흐름

`홈 → 상품 상세 → 장바구니 → 주문 완료` 화면과 세 Navigate를 만들었다.

- 화면, 블록, Button Navigate, 캔버스 connector, Flow, 화면별 Spec은 모두 구현상 가능했다.
- 한 행 네 화면 배치는 이번 과업에서 안정적이었지만 320px 간격 때문에 전체 조망에는 zoom out이 필요할 가능성이 컸다.
- Screen details 안에 Name, Purpose, Duplicate, Delete가 모여 있고 필드와 버튼 간격은 충분했다.
- 다만 Name과 Purpose가 접힌 details 안에 있고 blur로 저장되어 발견성과 저장 확신은 낮았다.
- Notes는 Prototype에 반영되지 않는 부수효과를 보존하지만 Destination과 같은 폼에 있어 실제 전환 동작의 일부로 오해할 수 있다.

판정은 **부분 성공**이다. 핵심 선형 prototype은 만들 수 있지만 전체 명세와 연결을 한 번에 검토하기 어렵다.

## 2차 과업 — 정상·오류 상태와 Overlay 요구

상품 상세와 장바구니 화면을 복제해 정상·오류 상태를 만들고, 목적 화면 삭제 뒤 연결을 복구했다.

- 프레임과 내부 요소, Section 계층은 온전히 복제되어 상태 화면의 출발점으로 유용했다.
- Figma의 일반적인 Duplicate 경험과 달리 reaction과 Feature는 조용히 제거됐다. 외형과 이름은 같은데 동작만 없어 리뷰 직전 누락 위험이 컸다.
- Delete는 incoming action과 reaction을 일관되게 정리했고 원래 버튼에는 새 action을 다시 설정할 수 있었다.
- 삭제 확인창이 들어오는 연결까지 제거된다는 영향 범위를 알리지 않고, 삭제 뒤 영향을 받은 버튼으로 돌아가는 경로도 없었다.

`장바구니 담기` Snackbar와 `재고 안내` Popup은 현재 두 action으로 실제 표현할 수 없었다. 별도 전체 화면 Navigate는 overlay, 닫기, 배경 유지, 자동 소멸을 재현하지 못하고 Describe는 문서에만 남는다.

## 최종 판정과 우선순위

전체 판정은 **부분 성공**이다.

1. Duplicate 직후 연결이 제외됐음을 명확히 알려야 한다.
2. Delete 확인에 제거될 incoming 연결 수와 출발 버튼을 표시해야 한다.
3. 최소 `Open overlay` 또는 Popup/Snackbar용 click-first 프리셋이 필요하다.
4. Notes/Describe가 Prototype에 반영되지 않는다는 경계를 입력 위치에서 설명해야 한다.
5. Spec 전체 화면 보기와 저장 완료 피드백이 필요하다.
